---
description: ไล่มาร์กฟิลด์ที่ยังไม่ได้ตัดสินให้จบ ทีละตัว
---

ช่วยผู้ใช้ปิดงานฟิลด์ที่ยังไม่ได้ตัดสินในโปรเจกต์นี้

1. รัน `node ${CLAUDE_PLUGIN_ROOT}/bin/arak.mjs status --json` เพื่อดูรายการทั้งหมด

2. ถ้าไม่มีฟิลด์ที่สถานะ `unmarked` ให้บอกว่าปิดงานครบแล้ว
   ถ้ามี `deferred` เหลืออยู่ ให้บอกยอดและถามว่าจะไล่เคลียร์หนี้เก่าด้วยไหม

3. อ่าน `purposes` ทั้งหมดในแคตตาล็อกก่อน แล้วจำไว้ว่ามีคีย์อะไรบ้าง

4. สำหรับแต่ละฟิลด์ที่ยังไม่ตัดสิน ให้เปิดสคีมาไปดูบริบทรอบ ๆ ก่อน — ชื่อ model
   ฟิลด์ข้างเคียง และคอมเมนต์ที่มีอยู่ มักบอกได้ว่าฟิลด์นี้ถูกใช้ทำอะไร

   แล้วเสนอกับผู้ใช้เป็นชุด ๆ ไม่เกินครั้งละห้าฟิลด์ ในรูปแบบ

   ```
   Customer.lineUserId   หมวดที่เสนอ: identity
                         วัตถุประสงค์ที่น่าจะใช่: delivery
                         เพราะ: อยู่ใน model เดียวกับที่อยู่จัดส่งและใช้ติดต่อผู้รับ
   ```

5. **ห้ามเติม `purposes` เองโดยไม่ได้ถาม** หมวดข้อมูลอ่านจากโค้ดได้
   แต่วัตถุประสงค์กับฐานทางกฎหมายเป็นการตัดสินใจของเจ้าของระบบ
   ให้เสนอพร้อมเหตุผล แล้วรอผู้ใช้ยืนยันหรือแก้

   ถ้าไม่มีวัตถุประสงค์ไหนในแคตตาล็อกตรงกับการใช้งานจริง **อย่าเพิ่มเข้าไปเอง**
   ให้บอกผู้ใช้ว่าต้องประกาศวัตถุประสงค์ใหม่ก่อน พร้อมถามว่าฐานทางกฎหมายคืออะไรและเก็บนานเท่าไร

6. เมื่อยืนยันแล้ว เขียนคอมเมนต์เหนือฟิลด์ในสคีมา

   ```prisma
   /// @pii(category=identity, purposes=delivery)
   lineUserId String?
   ```

   ฟิลด์ที่ไม่ใช่ข้อมูลส่วนบุคคลให้ใส่เหตุผลที่คนอ่านย้อนหลังแล้วเข้าใจ

   ```prisma
   /// @not-pii(reason="รหัสอ้างอิงภายใน สร้างแบบสุ่ม ไม่ผูกกับตัวบุคคล")
   refCode String
   ```

7. จบด้วย `node ${CLAUDE_PLUGIN_ROOT}/bin/arak.mjs sync` แล้วรายงานยอดที่เหลือ
