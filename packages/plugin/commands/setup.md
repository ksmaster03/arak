description: ตั้งค่า Arak ให้โปรเจกต์นี้ — หาสคีมา สร้างแคตตาล็อก แล้วตั้งเส้นฐาน
---

ตั้งค่า Arak ให้โปรเจกต์ที่เปิดอยู่ ทำตามลำดับนี้และรายงานผลแต่ละขั้นสั้น ๆ

1. เช็คก่อนว่ามี `arak.config.yaml` อยู่แล้วหรือยัง ถ้ามีแล้วให้ข้ามไปข้อ 4 และบอกผู้ใช้ว่าตั้งไว้แล้ว

2. รัน `node ${CLAUDE_PLUGIN_ROOT}/bin/arak.mjs init`
   ถ้ามันบอกว่าไม่พบไฟล์ `.prisma` ให้หยุดแล้วถามผู้ใช้ว่าสคีมาอยู่ที่ไหน

3. รัน `node ${CLAUDE_PLUGIN_ROOT}/bin/arak.mjs sync`
   ผลลัพธ์คือรายการฟิลด์ที่ตัวเดาคิดว่าน่าจะเป็นข้อมูลส่วนบุคคล

4. **หยุดตรงนี้แล้วถามผู้ใช้ก่อน** ว่าจะตั้งเส้นฐานเลยไหม พร้อมอธิบายให้ชัดว่า
   - ตั้งเส้นฐาน = ยกฟิลด์ที่มีอยู่แล้วทั้งหมดไปเป็น "หนี้เก่าที่รับรู้แล้ว"
     ยังโชว์ยอดทุกครั้งแต่ไม่ทำให้ CI ตก และปลั๊กอินจะไม่เตือนของเก่า
   - เหมาะกับโปรเจกต์ที่เขียนมานานแล้ว เพราะถ้าเตือนทุกฟิลด์ตั้งแต่วันแรกจะรำคาญจนเลิกใช้
   - ไม่ตั้งเส้นฐาน = ต้องไล่ตัดสินทุกฟิลด์ให้จบก่อน CI ถึงจะเขียว เหมาะกับโปรเจกต์ใหม่

   ถ้าผู้ใช้ตกลง ให้รัน `node ${CLAUDE_PLUGIN_ROOT}/bin/arak.mjs baseline`

5. เปิด `pii-catalog.yaml` แล้วช่วยผู้ใช้เติมสองส่วนที่เครื่องมือเดาแทนไม่ได้

   - `controller` — ชื่อและช่องทางติดต่อของผู้ควบคุมข้อมูล (ม.39(3))
   - `purposes` — วัตถุประสงค์การประมวลผลของระบบนี้ พร้อมฐานทางกฎหมายและระยะเวลาเก็บ

   **ถามผู้ใช้ อย่าเดา** วัตถุประสงค์กับฐานทางกฎหมายเป็นเรื่องธุรกิจและกฎหมาย ไม่ใช่เรื่องที่อ่านจากโค้ดแล้วรู้
   ค่าตั้งต้นที่ `arak init` ใส่ไว้เป็นแค่ตัวอย่าง ต้องแทนที่ด้วยของจริง

6. เตือนให้ commit `arak.config.yaml` กับ `pii-catalog.yaml` เข้า git
   สองไฟล์นี้คือของที่ทีมรีวิวร่วมกัน และเป็นต้นทางของ RoPA
