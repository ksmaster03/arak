# demo-app — สนามทดสอบของ Arak

แอปส่งของสมมติที่มีสคีมาเล็กพอจะอ่านจบในนาทีเดียว แต่ครบพอจะเจอกรณีที่น่าสนใจ
**ข้อมูลทุกอย่างในนี้แต่งขึ้น ไม่มีของลูกค้าจริง**

มีไว้สองอย่าง — เป็นเป้าให้ปลั๊กอินยิงเวลาพัฒนา Arak เอง
และเป็นตัวอย่างของ "แคตตาล็อกที่ปิดงานครบแล้ว" หน้าตาเป็นอย่างไร

## สถานะตอนนี้

```
มาร์กแล้ว 14 · ยังไม่ตัดสิน 0 · ระบุว่าไม่ใช่ 1
```

## สิ่งที่สคีมานี้จงใจใส่ไว้

| ตรงไหน | ทำไม |
|---|---|
| `Customer.refCode` | ตัวอย่างของ `@not-pii` ที่มีเหตุผลกำกับ — รหัสสุ่มที่ไม่ผูกกับตัวบุคคล |
| `Customer.email` | ฟิลด์เดียวที่รับใช้สองวัตถุประสงค์ (`delivery` และ `tax_invoice`) คนละฐานทางกฎหมาย |
| `Order.customerId` | กุญแจนอก ต้องไม่โผล่ในแคตตาล็อก |
| `Order.deliveryPhone` | ข้อมูลของ "ผู้รับ" ซึ่งอาจไม่ใช่คนสั่ง — คนละเจ้าของข้อมูลในตารางเดียวกัน |
| `Driver.nationalId` | เลขบัตรประชาชนที่มีวัตถุประสงค์ต่างจากของลูกค้า |
| `AuditLog.ip` | เก็บด้วยฐาน `legitimate_interest` ไม่ใช่สัญญา และเก็บสั้นกว่าที่อื่น |

```bash
cd examples/demo-app

# 1. เพิ่มฟิลด์ใหม่โดยไม่ใส่คำอธิบาย
#    เช่นเติม  lineUserId String?  เข้าไปใน model Customer

# 2. ดูว่าเครื่องมือพูดว่าอะไร
node ../../packages/cli/dist/index.js sync

# 3. ใส่คำอธิบายเหนือฟิลด์
#    /// @pii(category=identity, purposes=delivery)

# 4. ยืนยันว่าปิดงานแล้ว
node ../../packages/cli/dist/index.js status
```
